# راهنمای مرجع نمایش موقت HR Assist برای مدیر

این فایل نتیجهٔ فرایند موفق راه‌اندازی در تاریخ **۲۰۲۶-۱۱-۰۲** است. قبل از انتشار موقت، راه‌اندازی مجدد تونل یا بررسی خطای ورود آنلاین، آن را کامل بخوان.

## نیاز واقعی و انتخاب کاربر

مدیر باید از سیستم خودش یک لینک عمومی را باز کند. frontend روی Netlify است؛ backend، PostgreSQL و داده‌های برنامه روی کامپیوتر کاربر می‌مانند. درخواست AI از backend به Groq می‌رود؛ مدل AI روی کامپیوتر کاربر اجرا نمی‌شود.

انتخاب فعلی کاربر **فقط Cloudflare** است. بدون تغییر صریح این انتخاب، سراغ Railway، localhost.run یا انتقال دیتابیس نرو. اجرای صرفاً لوکال نیز پاسخ این نیاز نیست؛ مدیر نمی‌تواند پشت کامپیوتر کاربر بنشیند.

این راهنما به‌تنهایی مجوز ایجاد تونل، deploy، تغییر VPN یا انتقال داده نیست؛ اقدامات باید در محدودهٔ درخواست جاری باشند.

## معماری و تنظیمات تأییدشده

```text
مرورگر مدیر → Netlify frontend → proxy مسیرهای API
           → Cloudflare HTTPS tunnel → backend محلی 8001
                                    → PostgreSQL محلی / سرویس AI
```

| بخش | مقدار ثبت‌شده |
| --- | --- |
| لینک عمومی | https://hr-assist-137132cc.netlify.app/login |
| Netlify site ID | `1e841b4a-ede2-4201-b3a4-d20fd30087f9` |
| backend عمومیِ پشت تونل | `http://127.0.0.1:8001` |
| backend توسعهٔ عادی | `http://127.0.0.1:8000` |
| frontend توسعهٔ عادی | `http://127.0.0.1:5173` |
| شبکهٔ موفق این اجرا | v2rayN روشن، TUN فعال |
| پروتکل موفق تونل | `quic` |
| کوکی backend عمومی | `HR_COOKIE_SECURE=true` فقط در محیط همان فرایند |
| AI در این اجرا | Groq، مدل `qwen/qwen3.8-27b` |

نام مدل، وجود فایل‌ها و وضعیت فرایندها را دوباره بررسی کن؛ این جدول تضمین نمی‌کند که در آینده همان مقادیر در دسترس باشند.

## چرا تلاش اولیه طول کشید؟

1. deploy اولیه فقط frontend بود. ورود 404 نتلیفای می‌داد و `/api/me` به‌جای JSON، HTML برمی‌گرداند. backend متصل نبود؛ تغییر رمز یا CORS این وضعیت را حل نمی‌کرد.
2. قبل از TUN، HTTP/2 تونل قطع‌ووصلی داشت و خطاهای 502 و گاهی 530/1033 دیده شد. عوض‌کردن نسخهٔ ابزار و ایجاد تونل‌های متعدد راه‌حل نهایی نبود.
3. رفتار شبکهٔ مرورگر، درخواست مستقیم و پروکسی محلی یکسان نبود. بازبودن پنجرهٔ v2rayN به‌تنهایی سلامت ارتباط cloudflared را ثابت نمی‌کرد.
4. **بعد از روشن‌شدن TUN، تست داخلی cloudflared موفقیت QUIC و شکست HTTP/2 را نشان داد. اجرای تازه با `--protocol quic` به تست موفق انتها‌به‌انتها رسید.**

این نتیجه مخصوص شبکهٔ همین اجراست، نه قانون همیشگی Cloudflare. از مسیر موفق شروع کن؛ اگر شبکه عوض شده، خروجی تست اتصال و پاسخ واقعی HTTPS را مبنا قرار بده. بدون شواهد، نسخه‌های بیشتری دانلود نکن و deploy را تکرار نکن.

## ترتیب راه‌اندازی مجدد

### ۱. ابتدا وضعیت موجود را بررسی کن

از ریشهٔ پروژه `C:\Vahid\projects\hr-assist`، فایل `frontend/public/_redirects`، سلامت پورت 8001، PostgreSQL و TUN را بررسی کن. اگر backend یا تونل سالمی وجود دارد، فرایند تکراری نساز. پرسش‌ها را با کادر استاندارد سؤال بپرس؛ تنظیمات سراسری VPN را خودسرانه تغییر نده.

```powershell
Invoke-RestMethod http://127.0.0.1:8001/healthz
```

پاسخ مورد انتظار JSON با `status: ok` است. پورت باز یا صفحهٔ HTML، تأیید سلامت API نیست.

### ۲. در صورت نیاز backend اختصاصی را اجرا کن

در یک ترمینال تازه و اختصاصی:

```powershell
cd C:\Vahid\projects\hr-assist\backend
$env:HR_COOKIE_SECURE = 'true'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

این متغیر فقط در محیط همان ترمینال است. `.env` را بازنویسی نکن؛ اجرای HTTP عادی روی 8000 باید مستقل بماند. دیتابیس را به اینترنت باز نکن، دادهٔ کاربر را پاک نکن و برای این نمایش migration تخریبی اجرا نکن.

### ۳. پس از فعال‌بودن TUN، تونل QUIC بساز

وجود ابزار زیر را بررسی کن؛ فایل داخل runtime است و ممکن است در checkout دیگری موجود نباشد:

```text
.scratch/runtime/tools/cloudflared.exe
```

در صورت نبودن، فقط از [انتشار رسمی cloudflared](https://github.com/cloudflare/cloudflared/releases) دریافتش کن. از ریشهٔ پروژه، در ترمینال جدا:

```powershell
.\.scratch\runtime\tools\cloudflared.exe tunnel --protocol quic --logfile .scratch\runtime\manager-demo-quic.log --url http://127.0.0.1:8001
```

ترمینال باید باز بماند. URL واقعی `https://….trycloudflare.com` را از خروجی بردار، پیام `Registered tunnel connection` را بررسی و `/healthz` همان URL را تست کن. ساخته‌شدن URL به‌تنهایی کافی نیست.

آخرین آدرس موفق `https://simply-afford-accordingly-executives.trycloudflare.com` بود. **این مقدار تاریخی است؛ بعد از راه‌اندازی مجدد، آن را معتبر فرض نکن.**

### ۴. مقصد proxy را به آدرس سالم تازه تغییر بده

در `frontend/public/_redirects` سه قانون اول باید قبل از fallback باشند. `TUNNEL_HOST` را با hostname واقعی جایگزین کن؛ placeholder را deploy نکن:

```text
/auth/* https://TUNNEL_HOST/auth/:splat 200!
/api/* https://TUNNEL_HOST/api/:splat 200!
/healthz https://TUNNEL_HOST/healthz 200!
/* /index.html 200
```

مرورگر API و کوکی نشست را روی همان origin نتلیفای نگه می‌دارد. نیازی به انتشار کلید AI در frontend یا تبدیل درخواست‌ها به cross-origin نیست.

### ۵. فقط frontend را روی سایت موجود منتشر کن

```powershell
cd C:\Vahid\projects\hr-assist\frontend
npm run build
cd ..
npx --yes netlify-cli deploy --site 1e841b4a-ede2-4201-b3a4-d20fd30087f9 --dir frontend/dist --no-build --prod --message 'Temporary local backend via Cloudflare QUIC' --json
```

سایت جدید نساز. فقط `frontend/dist` را منتشر کن؛ `.env`، backend، اتصال دیتابیس و کلیدها نباید عمومی شوند. تغییر آدرس تونل بدون build و deploy مجدد، مقصد آنلاین را تغییر نمی‌دهد.

## قبل از اعلام موفقیت، روی Netlify تست کن

| بررسی | نتیجهٔ مورد انتظار |
| --- | --- |
| `GET /healthz` | HTTP 200 و JSON سلامت |
| `GET /api/me` بدون نشست | HTTP 401 و JSON، نه HTML |
| ورود با حساب آزمایشی معتبر | HTTP 204 و کوکی Secure/HttpOnly |
| `GET /api/me` بعد از ورود | HTTP 200 و هویت همان حساب |
| پروفایل و خلاصهٔ AI | محتوای واقعی و وضعیت درست خلاصه |
| جست‌وجوی ساده | پاسخ شامل رویداد پایانی `done` |
| خروج و بررسی مجدد نشست | HTTP 204، سپس HTTP 401 برای `/api/me` |

فایل‌های استفاده‌شده در این اجرا داخل `.scratch/runtime/` هستند؛ وجودشان را قبل از استفاده بررسی کن:

- `check_temporary_host.py`: تست نشست؛ با `--ai` بارگذاری رزومهٔ ساختگی و فراخوانی واقعی AI را هم بررسی می‌کند.
- `verify_temporary_online.py`: تست آدرس اصلی Netlify، نمایش نتیجهٔ AI ذخیره‌شده، جست‌وجو، ورود و خروج.
- `temporary-host-smoke-account.json`: اطلاعات حساب آزمایشیِ سازمان جدا، نه حساب اصلی کاربر.

اگر این فایل‌ها وجود ندارند، تست معادل را با دادهٔ ساختگی و حساب جدا انجام بده. رمز، کوکی، توکن و کلید API را وارد مخزن، راهنما یا لاگ عمومی نکن. رمز حساب اصلی را تغییر نده.

**خواندن خلاصهٔ ذخیره‌شده، تست فراخوانی جدید مدل نیست.** برای ادعای تولید زندهٔ AI، بارگذاری یا تولید واقعی باید موفق شده باشد. فراخوانی پرداختی را بی‌دلیل تکرار نکن و `error` یا `needs_review` را موفق گزارش نکن.

در این فرایند تولید واقعی رزومه و خلاصه با Groq بررسی شد. در اجرای نهایی QUIC، تست کامل نشست موفق بود و تست Netlify نیز ورود، نمایش پروفایل و خلاصهٔ آماده، اتمام جست‌وجو، خروج و لغو نشست را تأیید کرد.

## تشخیص سریع خطا

| نشانه | بررسی بعدی |
| --- | --- |
| 404 نتلیفای روی login یا HTML در `/api/me` | قوانین proxy، ترتیب قبل از SPA و deploy فعلی |
| 502، 530 یا Cloudflare 1033 | backend، زنده‌بودن تونل، URL تازه، TUN و ثبت اتصال |
| قطع HTTP/2 در این شبکه | مسیر تأییدشدهٔ TUN + QUIC و نتیجهٔ precheck |
| هشدار DNS | به‌تنهایی نتیجه‌گیری نکن؛ اتصال ثبت‌شده و پاسخ HTTPS را هم ببین |
| JSON با `LOGIN_BAD_CREDENTIALS` | backend پاسخ داده؛ مسئلهٔ حساب جدا از تونل است |
| خطای provider یا خلاصه | تنظیمات و پاسخ AI را جدا بررسی کن؛ خودکار به تونل نسبت نده |

اگر ابزار عملی را رد کرد، با روش غیرمستقیم دورش نزن؛ دلیل را دقیق گزارش کن و مسیر امن‌تر یا دارای مجوز لازم را دنبال کن. localhost.run در این فرایند اجرا نشد و کاربر Cloudflare را انتخاب کرد.

## محدودیت‌ها و تحویل

- کامپیوتر باید روشن و بیدار باشد؛ PostgreSQL، backend، تونل و v2rayN/TUN هم فعال بمانند. reboot این فرایندها را خودکار برنمی‌گرداند.
- `start.bat` فقط اجرای عادی لوکال است؛ backend اختصاصی 8001 و تونل عمومی را ایجاد نمی‌کند.
- با تغییر URL تونل، proxy و deploy باید دوباره به‌روز شوند.
- Quick Tunnel تضمین uptime ندارد. طبق [مستندات Cloudflare](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) از SSE پشتیبانی نمی‌کند؛ اتمام جست‌وجوی کوتاه در تست ما موفق بود، اما تحویل تدریجی یا درخواست‌های طولانی را تضمین نکن.
- AI رزومه، جست‌وجوی معنایی را خودکار فعال نمی‌کند؛ جست‌وجو تنظیمات مستقل `HR_SEARCH_*` دارد.
- برای توقف، فقط فرایندهای همین تونل و backend اختصاصی را پس از بررسی هویت فرایند ببند؛ سایر برنامه‌های کاربر را متوقف نکن.

در پایان، لینک Netlify و نیاز به روشن‌ماندن سیستم/TUN را بده. در صورت نیاز اطلاعات ورود دمو را از فایل محلی به کاربر بده؛ فایل را روی سایت منتشر نکن. تست موفق فعلی، تضمین پایداری دائمی نیست.
